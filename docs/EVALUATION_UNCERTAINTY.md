_Generated by `scripts/bootstrap_eval.py`; do not edit by hand._

## Method
- **Data:** held-out test split, **56 images / 746 labelled cells**; per-image predictions in `reports/predictions/` (exported with Ultralytics validation settings).
- **Resampling:** image-level bootstrap, **B = 2000**, seed 42, 95% percentile bootstrap intervals.
- **Design:** paired (identical resampled image sets for all models); model differences are computed within each resample.
- **Detection metrics:** per-image TP statistics captured from Ultralytics model.val() (multi-label NMS), re-aggregated with ultralytics ap_per_class (IoU 0.50:0.95).
- **Counting metrics:** mean absolute per-image count error at per-class, calibrated on the val split (see reports/metrics/<run>.json); source: counts produced through the serving configuration (model.predict, single-label NMS, API NMS IoU and confidence floor).

## How to read this
- **Resolved** means the 95% interval of the paired difference excludes 0 on this test set.
- **Not resolved** means this test set cannot tell the models apart on that metric. It does **not** show the models are equivalent; an equivalence claim would need a pre-registered margin and an interval that falls entirely inside it.

## Limitations
- Small test set (56 images): percentile intervals from small samples tend to be too narrow; treat them as approximate.
- Single source (one lab, stain and microscope); intervals describe sampling variability within BCCD, not generalisation to other sites.
- Image independence is assumed. BCCD does not document patient or slide IDs, so correlated images could make intervals optimistic.
- Ground truth has missing RBC annotations, which biases RBC precision/count metrics; the bootstrap quantifies sampling noise, not label noise.
- Several metrics and comparisons are reported without multiplicity correction.
- Counting thresholds were tuned on the val split (not test), but only one train/val split was used.
